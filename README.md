# 明势 Míngshì · AI 驱动的 A 股市场大势研判

> 把「市场现在处于什么状态」拆成七个可复核的读数，把「为什么这么判断」写成可检验的机制，
> 把「什么情况下判断会变」变成 8 条带阈值的条件。
> **不预测涨跌，不给仓位建议**——这不是免责声明，而是代码里的硬约束。

同花顺 2026 秋招 AI 产品笔试题答案。

## 30 秒跑起来

```bash
cd mingshi
python run.py                  # 启动并自动打开浏览器（http://127.0.0.1:8765）
python run.py --no-open        # 只启动服务
python run.py --port 9000      # 换端口
python run.py report -o 研判.md # 不启动服务，直接导出 Markdown 研判
python run.py doctor           # 体检：数据源可达性 / 缓存 / 快照
```

* **零第三方依赖**：只要 Python 3.10+（标准库 `urllib` / `http.server` / `json`）。
  评分机器上不需要 `pip install`、不需要 Node、不需要 API Key。
* 首次启动会联网取一次数据（约 8 秒，20+ 个并发请求），随后写入 `data/snapshots/<日期>.json`；
  断网或数据源全部不可用时，自动回退到最近一份快照，页面上会明确标注「离线快照」。
* 仓库内已附 `data/snapshots/2026-10-23.json`，**完全离线也能看到完整产品**。

## 产品长什么样

| 区块 | 回答的问题 |
| --- | --- |
| 状态卡（Hero） | 今天是什么状态、置信度多少、趋势轴/风险偏好轴各在哪 |
| 七维证据 | 结构/宽度/轮动/估值/流动性/情绪/事件，每维给读数、关键数据、口径、局限 |
| 二维状态图 | 七个维度按轴加权落到一张「趋势 × 风险偏好」图上 |
| 主要矛盾 | 哪两个维度在互相打脸、这个背离通常意味着什么、怎么验证 |
| 条件清单 | 判断可能改变的条件：当前值 / 阈值 / 距离 / 触发后状态怎么变 |
| 风格轮动 | 行业与板块的强弱、持续性（秩相关） |
| 数据健康 | 每个数据源用了主源还是备源、取数耗时、缺失项 |
| 追问 | 自然语言问当前状态（交易类问题会被改写为「状态+条件」） |

## 为什么这样设计

1. **有状态的研判，而不是一张图**。先定性当前状态（五态：共振上行 / 结构分化 / 震荡分化 / 超跌修复 / 无序高波动），
   再在状态内解释矛盾，最后给离开该状态的条件。读数随数据变化，结论随读数变化。
2. **七维不是凑数，是互相打脸用的**。指数涨、宽度跌（指数强撑、个股走弱）才是信息；
   单看任何一维都只是行情。矛盾检测是产品的主体，不是附赠。
3. **条件优先于结论**。8 条条件各带当前值、阈值、距离（%或 pp）和触发后的状态迁移，
   用户可以自己复核「我还该不该相信这个判断」。
4. **数字必须可追溯**。每个读数都能点开看到构成它的原始值、单位和来源；
   界面上的每个数字都能在「数据与口径」里找到出处。
5. **合规是代码，不是提示词**。`app/compliance.py` 用 11 条正则审查所有对外文本，
   命中的片段被替换为中性表述；LLM 生成的叙述还要再过一道数字校验（见 `docs/AI_USAGE.md`）。

## 架构

```
run.py                 启动器 / CLI（serve、report、doctor）
app/
  net.py               urllib 封装：超时、重试、并发、IPv4 强制
  source.py            数据源适配器：EastMoney / Sina / Tencent / Fuyao(同花顺扶摇，可选)
  fetch.py             能力路由：每个能力按优先级试主源与备源，记录 provenance 与降级链
  indicators.py        纯函数指标：MA / 收益 / 波动率 / 分位 / 秩相关（可逐行手算复核）
  evidence.py          七维证据构建：每维输出 score / facts / signals / caliber / uncertainty
  regime.py            状态机：二维定位、矛盾检测、条件生成、状态迁移
  narrate.py           叙述生成：确定性模板（默认）/ LLM 改写（可选，过数字校验）
  compliance.py        合规审查与净化
  qa.py                追问检索：意图识别 → 证据检索 → 回答 + 引用
  report.py            Markdown 研判导出
  store.py             快照存取、历史序列
  engine.py            编排：取数 → 证据 → 状态 → 矛盾 → 条件 → 叙述 → 审计 → 落盘
  api.py               标准库 HTTP 服务（GET /api/dashboard 等）
web/                   index.html + style.css + app.js（手写 SVG 图表，无第三方库）
tests/test_core.py     36 个单元测试（离线、无依赖）
docs/                  PRODUCT / DATA / AI_USAGE / TESTING
```

## 数据

全部来自公开行情接口（东方财富 / 新浪财经 / 腾讯证券），每个能力都有主源与备源，
降级链记录在 payload 的 `data_health.fallbacks` 里并在界面上展示。
字段口径、单位、已知缺陷见 [docs/DATA.md](docs/DATA.md)。

## 合规边界

* 不出现方向预测（「预计下周上涨」「目标位 3800」）、不给仓位与买卖建议、不做评级。
* 所有对外文本（叙述、追问回答、Markdown 导出）在离开服务端前都过 `compliance.audit()`，
  违规片段被 `scrub()` 替换；违规项同时暴露在接口里，便于审计。
* 追问里遇到交易类问题（「现在能买吗」）不会顺着答，而是重框定为「当前状态 + 改变条件」。

## 已知限制

* 市场宽度用全市场快照（约 5200 只）计算，接口偶发限流时会降级为抽样，`data_health` 会标注。
* 估值维度依赖指数静态 PE/PB，不同源口径略有差异，界面只呈现分位不呈现绝对值对比。
* 事件维度基于关键词词典（17 类）命中，不做语义理解；命中率低时会明确显示「无显著单一事件驱动」。
* LLM 叙述为可选增强，未配置 Key 时使用确定性模板，两者共享同一套数字与合规审查。
