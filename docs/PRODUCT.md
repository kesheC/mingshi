# 产品设计说明 · 明势 Míngshì

> 这份文档说明产品解决什么问题、为什么用「状态」而不是「预测」组织信息、
> 七个维度与五个状态的取舍依据，以及合规约束如何落进产品结构而不是免责声明。

## 1. 用户与场景

### 1.1 用户

A 股市场的**研究与策略工作者**：券商与基金的研究员、投资经理、有自己框架的成熟个人投资者。他们的日常不是「今天买什么」，而是每天开盘前用二十分钟回答两个问题：

1. 昨天的市场发生了什么，今天和昨天相比，结构上有什么不同？
2. 我原来对市场的判断还成立吗？如果不成立，是哪一条证据先变了？

这类用户有能力读数字，也有能力质疑结论。他们不缺信息，缺的是把信息组织成**可复核判断**的结构。

### 1.2 现有工作流的断点

| 现有做法 | 断点 |
| --- | --- |
| 同时打开行情、涨跌分布、行业排名、两融、新闻流 | 信息是并列的，没有「哪两条在互相矛盾」的组织方式 |
| 读卖方晨报的结论段 | 结论通常没有可证伪条件：对了不知道对在哪，错了不知道错在哪 |
| 看事后归因 | 同一套说辞可以解释任何一天的行情，无法复现，也无法证伪 |
| 自己拼 Excel | 口径不统一、跨源拼接易错，历史序列难以沉淀 |

核心问题是**信息过剩而可复核的判断稀缺**。产品不增加信息，而是把已有的公开数据压缩成一条可被质疑的判断链。

### 1.3 产品的交付物

不是观点，而是三样可以被质疑的东西：

1. 一个**状态标签**：今天是哪一类市场，置信度多少，落在两条轴的什么位置；
2. 一组**互相制衡的读数**：七个维度各自的强弱、读数构成、口径与不确定点；
3. 一份**能改变判断的条件清单**：当前值、阈值、距离、是否已触发。

用户拿走这三样东西，自己决定要不要推翻原有判断。产品不替用户下结论，也不替用户做交易决定。

## 2. 核心问题定义

传统行情产品回答「涨了还是跌了」，荐股产品回答「买什么」，明势回答的是：

> **当前市场处在什么状态？这个状态的支撑是什么、裂缝是什么？什么条件下这个判断必须被推翻？**

这个问题的三个特征决定了产品形态：

- **状态是多维的**：单一指标（指数涨跌、涨停家数）无法区分「指数强撑、个股走弱」与「全面走强」，必须把多个维度并置；
- **状态是相对的**：同一个读数在不同历史位置含义不同，所以需要分位、距离与历史对照，而不是绝对值；
- **状态会变，且变化有前兆**：把「什么条件下会变」写成可监控的阈值，比给一个目标点位更有用，也更可检验。

## 3. 四层信息架构：状态—证据—矛盾—条件

产品把一次研判拆成四层，页面的阅读顺序与推理顺序一致。

```text
状态（state）        今天是什么状态、置信度、两条轴的位置
  ↑ 由什么支撑
证据（evidence）     七维读数、事实、口径、来源、局限
  ↑ 哪里不稳
矛盾（contradiction）哪两维在打架、强度多少、怎么验证
  ↑ 何时失效
条件（conditions）   当前值 / 阈值 / 距离 / 是否触发；以及推翻状态的条件
```

四层之间的约束：

- **向下可追溯**：状态由两条轴加权得到，轴由七维读数加权得到，每个读数都能回到 `Fact` 与原始来源（`source` 形如 `tencent::index_kline`）；
- **向上可推翻**：任何一条证据的缺失会降低 `coverage`，任何两维的背离会降低 `consistency`，两者都会压低置信度；条件触发则直接要求重新评估状态；
- **层间不重复**：证据层只陈述读数，不下结论；矛盾层只描述冲突，不预测胜负；条件层只给阈值与距离，不给操作。

这一结构也解释了产品为什么不做「一句话多空」：一句话结论会把四层压成一层，用户失去复核入口。

## 4. 七个维度：为什么是这七个

每个维度必须满足三个条件：**能独立取数、能独立计算、能与其他维度冲突**。只满足前两条的指标（例如北向资金、机构调研）被排除，因为它们要么不可得，要么无法与当日价格形成可验证的张力。

| 维度 | 回答的问题 | 轴 / 权重 | 关键读数 | 它能和谁冲突 |
| --- | --- | --- | --- | --- |
| 行情结构 | 价格处在什么位置？趋势是有序还是紊乱？ | 趋势 / 0.22 | 三大指数相对 MA20/60/120、20 日均线 5 日斜率、250 日回撤、波动率分位 | 指数可靠权重股撑住，与宽度、情绪背离 |
| 市场宽度 | 指数的涨跌，有多少股票在跟？ | 趋势 / 0.20 | 上涨占比、涨跌中位数、涨跌超 5% 家数、涨跌停家数、±1% 横盘占比 | 指数涨而中位数跌，是内部先坏 |
| 风格轮动 | 钱在往哪类资产走？轮动是在加速还是收敛？ | 趋势 / 0.15 | 大小盘与成长/红利价差、行业 5/20 日收益、离散度、排名秩相关 | 轮动过快说明没有主线，与「趋势稳」相反 |
| 估值 | 当前价格需要用多少盈利来兑现？市场还有多少安全垫？ | 风险 / 0.12 | 全 A 中位 PE(TTM)/PB、破净率、PE>80 占比、亏损占比、历史分位 | 低估可以更低估，与情绪、流动性常背离 |
| 流动性 | 支撑当前价格的钱，是变多了还是变少了？ | 风险 / 0.13 | 成交额、成交活跃度、换手率中位数、两融余额与 5 日变化、主力净流入 | 缩量上涨是流动性在拆趋势的台 |
| 情绪 | 短线资金的赚钱效应如何？进攻意愿是在扩张还是收缩？ | 风险 / 0.11 | 涨停/跌停家数、最高连板、连板股数量、封板率、封单额中位数 | 情绪先于价格转向，与结构错位 |
| 重要事件 | 这两天有没有会改变定价逻辑的事情发生？ | 风险 / 0.07 | 资讯标题命中 16 组事件规则（9 类）的方向读数 | 事件是外生的，可以与其余六维全部相反 |

权重不是「重要性排名」，而是**这份报告里各维度的解释责任**：结构 0.22 最高，因为它直接定义价格体系；事件 0.07 最低，因为词典匹配的确定性最弱，且它只在少数交易日提供增量信息。趋势轴内部权重为结构 0.45、宽度 0.35、轮动 0.20；风险轴内部为估值 0.20、流动性 0.30、情绪 0.30、事件 0.20。维度权重回答「在报告里多重要」，轴内权重回答「在这条轴上多重要」。

刻意不做的维度：

- **北向资金**：披露口径变化后，日频不可得，强行拼接会制造虚假精度；
- **机构调研/龙虎榜**：滞后、样本选择偏差大，难以形成当日可验证的读数；
- **技术形态识别**：可解释性差，参数一多变，无法让用户复核。

## 5. 状态机设计

### 5.1 两条轴

七个维度的量纲统一到 `[-1, 1]`，0 为中性。按语义归到两条轴：

```text
趋势强度 trend = 0.45×结构 + 0.35×宽度 + 0.20×轮动
风险偏好 risk  = 0.20×估值 + 0.30×流动性 + 0.30×情绪 + 0.20×事件
```

两条轴回答不同问题：趋势轴是「价格体系在往哪边倾斜」，风险偏好轴是「资金愿不愿意承担风险」。**同向才是共振，反向才是分化**——这是整个产品最核心的一句话。轴在计算时按可用维度重新归一，缺失维度不会把轴拉向 0，而是降低覆盖率。

### 5.2 五个象限态 + 一个覆盖态

| 状态码 | 名称 | 象限 | 判定 |
| --- | --- | --- | --- |
| `resonance_up` | 共振偏强 | 右上 | trend > +0.15 且 risk > +0.15 |
| `structural` | 结构性偏强 | 右下 | trend > +0.15 且 risk < −0.15 |
| `bottom_probe` | 底部博弈 | 左上 | trend < −0.15 且 risk > +0.15 |
| `resonance_down` | 共振偏弱 | 左下 | trend < −0.15 且 risk < −0.15 |
| `range_split` | 震荡分化 | 中枢 | 至少一条轴落在 ±0.15 的中性带（含轴缺失） |
| `disorder` | 高波动失序 | 覆盖态 | 见 5.3 |

四个象限态描述「方向 + 风险偏好」的组合；`range_split` 是中性带内的默认态，不是「没有状态」，而是「方向尚未形成共识」这一状态本身。

### 5.3 ±0.15 与 disorder 的阈值理由

**±0.15 是中性带的半宽。** 七维读数被 `clamp` 到 `[-1, 1]`，轴是加权平均，因此轴也落在同一量纲。0.15 相当于量表宽度的 15%：读数在 0 附近的小幅漂移不应被命名成一个方向性状态，否则产品会每天在「偏强/偏弱」之间抖动，状态失去信息量。这个值不是统计校准的结果，而是**产品对「不要把噪音命名成状态」的显式约定**；它可配置（`NEUTRAL_BAND`），也应在积累足够快照后用状态稳定性与条件触发率去检验。

**disorder 用两条不一致的守卫，是刻意的：**

1. 象限判定**之前**：`vol_pct ≥ 0.85 且 consistency < 0.6` → 直接判为 disorder。波动率处于近 250 日的前 15%，同时证据不够一致，此时任何象限标签都不可信；
2. 象限判定**之后**：`consistency < 0.3 且 vol_pct ≥ 0.8` → 覆写为 disorder。这是兜底：即使两条轴恰好都越过了 ±0.15，只要七维内部离散到几乎随机、且波动率仍在高位，也不应给出方向性状态。

两条守卫的阈值不同，是因为它们回答的问题不同：第一条问「高波动 + 中等不一致，是否已经不该给方向」，第二条问「极端不一致 + 高波动，是否必须收回方向」。二者是「或」的关系，不会互相覆盖。阈值同样不是统计校准值，代码与文档都把它当作可讨论的产品参数。

### 5.4 子状态

状态内部再切一刀，因为同一个「震荡分化」可能对应完全相反的内部结构：

| 条件 | 子状态 |
| --- | --- |
| structure ≤ −0.4 且 breadth ≥ +0.5 | 超跌修复初期（宽度先修复、结构未修复） |
| structure ≥ +0.4 且 breadth ≤ −0.5 | 指数强撑、个股走弱（结构未破、内部先坏） |
| structure ≤ −0.4 且 breadth ≤ −0.5 | 普跌加速（价格与宽度同步恶化） |
| structure ≥ +0.4 且 breadth ≥ +0.5 且 sentiment > 0.3 | 多点共振（结构、宽度、情绪同向向上） |

2026-10-23 的实际运行结果是第一种：结构 −0.84（明显偏弱）、宽度 +0.90（明显偏强），状态「震荡分化 / 超跌修复初期」。只看指数会得出相反结论，只看涨跌家数会错过结构风险——这正是四层结构要保留的信息。

### 5.5 置信度

```text
confidence = 100 × (0.35×coverage + 0.35×consistency + 0.30×freshness)
disorder 状态下 × 0.85
```

- `coverage`：七维中有读数且非 missing 的权重占比；
- `consistency`：`clamp(1 − mad/0.6, 0, 1)`，`mad` 是七维读数相对加权均值的加权平均绝对偏差；
- `freshness`：freshness 为 `fresh` 的权重占比。

三个因子同时返回（`confidence_parts`），让用户区分「结论弱」与「数据弱」。一个永远 70 分的置信度没有信息量；把覆盖率、一致性、新鲜度拆开，才知道该不该信。

## 6. 为什么把「矛盾」作为一等公民

状态是聚合结果，聚合会掩盖分歧。两个维度反向时，加权平均可能刚好落在中性带，给出一个看似平稳的「震荡分化」——但真实的信号恰恰是分歧本身。

因此产品把矛盾放在证据之后、条件之前，并且：

- **有专门的矛盾库**，而不是任意两维相减。当前 5 对：结构×宽度「指数与个股背离」、估值×情绪「估值与情绪错位」、流动性×情绪「情绪与资金错位」、结构×流动性「价格与量能不同步」、轮动×宽度「风格极致与整体赚钱效应背离」。每一对都有明确的金融含义与验证方式；
- **强度可计算**：`strength = (|a−b|/2) × (wa+wb)/0.4`，同时考虑读数差与两维权重；读数差为 2（一个 +1 一个 −1）且权重和为 0.4 时强度为 1；
- **有兜底**：如果五对都没有达到阈值，取权重最高且方向相反的一对，避免「今天没有矛盾」这种无信息输出；
- **最多展示两条**：矛盾不是越多越好，超过两条会让用户无法排序，也说明状态本身不稳定。

矛盾直接进入叙述与追问：追问里问「为什么」，回答必须引用具体的两维读数和强度，而不是给一个笼统的解释。

## 7. 可证伪条件的意义

产品有两类条件，职责不同，不能混为一谈：

### 7.1 `switch_conditions`：判断可能改变的条件

8 条基础条件，覆盖价格位置、市场宽度、成交活跃度、两融变化、涨跌停温度与波动率：

| id | 条件 | 阈值 | 比较 |
| --- | --- | --- | --- |
| `sh_ma60` | 上证相对 MA60 | ≤ 0% | ≤ |
| `sh_ma20` | 上证相对 MA20 | ≤ 0% | ≤ |
| `breadth_50` | 上涨家数占比 | ≤ 50% | ≤ |
| `activity` | 两市成交活跃度 | ≤ 0.85 倍 | ≤ |
| `margin_5d` | 两融余额 5 日变化 | ≤ 0% | ≤ |
| `zt_count` | 涨停家数 | ≤ 40 家 | ≤ |
| `max_board` | 最高连板 | ≤ 3 板 | ≤ |
| `vol_pct` | 波动率历史分位 | ≥ 85% | ≥ |

弱态（`resonance_down` / `bottom_probe`）追加 `breadth_recover`（上涨占比 ≥ 55%），强态（`resonance_up` / `structural`）追加 `breadth_deteriorate`（上涨占比 ≤ 40%），因此一次输出通常是 8–10 条。状态专属条件的 `current` 恒为 `None`，只作为待监控阈值展示，不假装已经取到数。

每条条件都带：

- `current`：当前值；
- `threshold`：阈值；
- `distance_pct`：距离。阈值非 0 时是相对阈值的百分比 `|current−threshold|/|threshold|×100`；阈值为 0 时改用百分点差，并置 `distance_is_pp=True`，避免除零；
- `triggered`：是否已触发；
- `why`：这条条件为什么重要。

页面上优先展示「未触发且距离最近」的 4 条（叙述层逻辑），完整清单在条件页。这样用户看到的是「最可能先变的那几条」，而不是十条并列。

### 7.2 `state_triggers`：当前状态被推翻的条件

每个状态有 2 条更宏观的推翻条件，例如：

- `resonance_up`：宽度回落到 55% 以下，或波动率升破 85% 分位；
- `range_split`：两条轴同时越过 ±0.15，或波动率升破 85% 分位且一致性低于 0.5；
- `disorder`：波动率回落到 80% 分位以下，且七维离散度 ≤ 0.45。

`switch_conditions` 回答「哪些读数在逼近阈值」，`state_triggers` 回答「什么情况下这个状态本身不成立」。后者是给状态机的退出条件，也是「可证伪」在产品上的最终落点：如果一个状态没有任何可观测的推翻条件，它就不是判断，而是信仰。

## 8. 交互设计

### 8.1 信息顺序

首屏给出：状态名、置信度环、趋势/风险两条轴、状态地图上的当前位置。第二屏是七维证据卡片，第三屏是矛盾，第四屏是条件，第五屏是轮动与数据健康。顺序即论证顺序：**先知道今天是什么日子，再决定要不要相信它**。

### 8.2 状态地图

- 横轴为趋势强度，纵轴为风险偏好（向上为正）；
- 四个象限有底色与标签，`disorder` 作为覆盖态用特殊标记，不与象限混淆；
- 当前点用光晕 + 实心圆 + 状态名标注，避免用户在图里找不到自己；
- 地图不是预测图：它只展示当前位置，不画箭头、不给目标区域。

### 8.3 七维雷达

- 七个轴按固定顺序排列（结构、宽度、轮动、估值、流动性、情绪、事件）；
- `[-1, 1]` 映射到半径区间 `[0.16R, R]`，0 值落在内圈而不是圆心，避免「中性」被误读为「没有数据」；
- 雷达只做形状比较，不标「好/坏」；读数、状态词、口径在卡片里给出。

### 8.4 证据卡片

每维一张卡，包含：状态词（明显偏强/偏强/中性/偏弱/明显偏弱）、score、置信度、一句判读、事实表（label / value / unit / source）、口径说明、局限（uncertainty）。事实表默认折叠，展开后可以看到构成读数的原始数字。

### 8.5 追问

追问框提供固定 chips（「现在是什么状态」「主要矛盾是什么」「什么条件下判断会变」「宽度现在什么水平」），也接受自由输入。回答带引用条：维度 id、事实 label、数值、来源。交易类问题（能买吗、仓位、目标价、看多/看空）不进入生成链路，直接拒答并重框定为状态与条件。

### 8.6 数据健康

单独一页，展示数据源目录、每个能力的实际供数方、降级链、`ok_ratio`、错误列表与逐条取数日志。数据质量不是设置页里的隐藏项：一个不敢暴露数据来源与缺失的研究产品，不值得信任。

## 9. 合规边界如何内建

合规不是页脚的免责声明，而是三层结构性约束：

### 9.1 输出对象约束

产品输出的是**状态、证据、矛盾、条件**，没有「买/卖/仓位/目标价」这些字段。数据模型里不存在这类字段，因此不可能在前端被「顺手」渲染出来。

### 9.2 文本审计

`app/compliance.py` 用 9 条正则覆盖 6 类风险表述：

| 类别 | 条数 | 例子（会被拦截的表述） |
| --- | ---: | --- |
| 方向预测 | 2 | 「预计上涨」「看多」 |
| 点位预测 | 2 | 「目标位 3800」「看到 4000 点」 |
| 交易建议 | 2 | 「建议买入」「逢低加仓」 |
| 仓位建议 | 1 | 「仓位提到七成」 |
| 绝对化表述 | 1 | 「必然」「一定会」 |
| 评级表述 | 1 | 「买入评级」「增持」 |

命中后 `scrub()` 替换为中性表述，同时 `audit()` 返回违规项、检查字符数与规则清单。编排层当前审计叙述的 `headline` 与 `summary`；追问的 LLM 输出额外过 `scrub()` 与数字校验；检索式回答由确定性模板生成；Markdown 导出由已生成字段拼装。**覆盖缺口是已知的**：维度 facts、检索式问答、Markdown 正文没有逐条再审，且「建议仓位提升至 7 成」这类句式当前规则会漏检（测试已暴露）。文档不把「全部文本都过审计」写成事实。

### 9.3 追问拒答

`app/qa.py` 维护 17 个交易类词（能买、可以买、该买、买什么、推荐、仓位、加仓、减仓、清仓、止损、止盈、抄底、入场、出局、目标价、看多、看空）。命中即进入 `_refuse_trade`，返回 `refused=true, engine="guardrail"`，并把问题重框定为「当前状态 + 改变条件」。拒答不是把问题丢掉，而是把它转成产品能负责的问题。

### 9.4 免责声明

所有页面与导出统一带：

> 本内容为市场状态描述与条件推演，基于公开行情数据，不构成投资建议，不预测涨跌，不提供买卖与仓位建议。

## 10. 与「荐股产品」的本质区别

| 维度 | 荐股产品 | 明势 |
| --- | --- | --- |
| 输出 | 标的、方向、买卖点、仓位 | 状态、证据、矛盾、条件 |
| 判断单位 | 一次交易 | 一段可复核的状态描述 |
| 时间尺度 | 目标价对应的持有期 | 当日截面 + 条件触发后的状态迁移 |
| 成功标准 | 涨跌命中率 | 状态稳定性、条件触发率、矛盾验证率 |
| 不确定性 | 通常被隐藏或口头提示 | 拆成 coverage/consistency/freshness 三个可展示因子 |
| 用户动作 | 跟随 | 复核、质疑、自己决定 |
| 失效方式 | 错了不承认，或事后改口 | 条件触发即要求重新评估，状态可被推翻 |
| 合规 | 依赖话术规避 | 输出模型里不存在交易字段，文本层另有审计与拒答 |

最根本的区别是**判断的归属**：荐股产品把判断交给产品，用户执行；明势把证据与条件交给用户，判断仍归用户。产品只对「描述是否准确、条件是否可监控」负责，不对涨跌负责。

## 11. 如何判断产品有用

| 指标 | 定义 | 为什么是它 |
| --- | --- | --- |
| 状态稳定性 | 同一状态连续出现的中位天数 | 天天换状态的产品没有信息量 |
| 条件触发率 | 每周触发条件数 / 展示条件数 | 太松（天天触发）或太紧（永不触发）都说明阈值没校准 |
| 矛盾验证率 | 矛盾出现后 5 日内被价格结构验证的比例 | 检验「背离」是不是真有领先性 |
| 追问重框定率 | 交易类问题被重框定的比例 | 衡量用户是否把它当研究工具而非荐股器 |
| 复核深度 | 证据卡片展开率、`source` 的查看率 | 可追溯性是否被真正使用 |

前四个都可以离线算（依赖历史快照），不需要埋点就能做首轮校准。

## 12. 不做什么

- **不做个股**：个股研判必然滑向荐股，产品边界停在大势；
- **不做预测准确率**：没有可比的基准，任何「准确率 70%」都是自证；
- **不做实时高频**：A 股大势的决策频率是天，秒级刷新只会制造噪声与限流；
- **不做自动交易信号**：与合规红线冲突；
- **不做多市场混合**：港股/美股的宽度与情绪口径不同，混在一套模型里会互相污染；
- **不把 LLM 放在判断链路上**：LLM 只做语言组织与追问增强，读数、阈值、状态、合规全部是确定性代码（见 `docs/AI_USAGE.md`）。

## 13. 如果继续做

1. **状态历史与迁移矩阵**：把每日快照串起来，回答「上次出现这个组合之后，状态怎么迁移」；`store.history()` 已有数据结构，缺可视化与统计。
2. **条件回测**：8–10 条条件在历史快照上的触发率与后续状态分布，用来校准阈值，而不是拍脑袋。
3. **矛盾强度校准**：当前 `strength` 是读数差与权重的线性映射，应改为历史分位。
4. **事件维度升级**：从关键词词典换成本地小模型分类器，但必须保留命中片段与方向可解释性。
5. **中性带可配**：短线与长线用户对「中性」的定义不同，`NEUTRAL_BAND` 应可配置，并展示不同带宽下的状态敏感性。
